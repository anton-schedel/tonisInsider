# Coach Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A password-protected page `/schnoeselmob/` where the TuS Schnöselmob coach writes and schedules lineup, result and player-news posts, with optional bot comments written by an LLM.

**Architecture:** Posts live in D1 (`coach_posts`, `coach_images`). Worker API routes under `/api/coach/` handle login, CRUD, images and a token-protected export. The 5-minute scrape run fetches the export, writes `store/coach-posts.json` and the photos, and rebuilds when it changed; `src/lib/data.ts` turns them into `Article`s (pure `toArticle`). Future posts are built up to 7 days ahead and revealed client-side at their minute. Bot comments are generated by the Worker on save (OpenAI-compatible chat API, Morpheus) and stored as future-dated rows in the existing `comments` table.

**Tech Stack:** Astro 7 on a Cloudflare Worker, D1, Tailwind 4, Vitest, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-22-coach-page-design.md`

## Global Constraints

- Coach post ids start at `900001000` (inside `isOwnPost`: 900000000 ≤ id < 1000000000).
- Club: `{ id: 0, slug: "tus-schnoeselmob", name: "TuS Schnöselmob", crest: "/brand/schnoeselmob.png" }`, `source: { name: "TonInsider" }`, `own: true`, `category: "bundesliga"`.
- Lineup URL `/tus-schnoeselmob/aufstellung-des-tus-schnoeselmob-<id>/`, body "Startelf: … <br> Bank: …" so `confirmedLineup` shows the XI.
- Cookie `coach`: 90 days, `HttpOnly; Secure; SameSite=Lax; Path=/`, HMAC-SHA256 with `CREDENTIALS_KEY`.
- Login rate limit: 5 wrong tries per IP in 10 minutes.
- Images: JPEG only, ≤ 600 KB after the browser shrinks them to ≤ 1200 px, q 0.82.
- Validation: headline 3–140 chars, score 0–99, publish time ≤ 60 days ahead, pin 0–24 h.
- Bot comments: about 30, minutes 0–18 after publish, `sender = 'bot'`, model call timeout 120 s, run from a separate request (`POST /api/coach/bots/:id`) after the save; lineup rows labelled Tor/Abwehr/Mittelfeld/Sturm in the prompt.
- Secrets never printed or committed; the repo is public and code-only.
- German UI copy, calm Apple-like design, light and dark, 360 px wide without horizontal scroll.

## Review Focus

1. Saving a post while the cookie expired: the form keeps its content and asks for the password again.
2. A model answer that isn't clean JSON (code fences, prose around it, trailing commas): the parser still finds the list or gives up cleanly; the post is saved either way.
3. Names with umlauts and HTML characters (`<`, `&`) in lineup fields and text: escaped in the body, shown correctly.
4. A post scheduled while the feed is already open: the row stays hidden until its minute, then shows without a reload (existing `data-show-after` reveal runs on navigation; acceptable) and is never shown before.
5. Export fetch failing in CI: the last `store/coach-posts.json` stays and the run doesn't fail.
