# TonInsider iOS App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native SwiftUI TonInsider app (News, Aufstellungen, Mein Team, Scouting, Einstellungen) that feels as
instant as Kickbase, fed by the existing Worker, without changing the website.

**Architecture:** Three small server additions: (1) a Worker-level adapter that turns an app's bearer token into
the cookies the existing endpoints already read, and their `Set-Cookie` back into a new token — so every existing
endpoint works for the app unchanged; (2) a prerendered `/data/app-feed.json` with the finished feed; (3) Mein
Team's data loading moved into `myTeamData()`, used by the page and a new `/api/app/my-team/`. The app keeps the
feed on disk (shown at once, refreshed with a conditional GET) and renders everything natively.

**Tech Stack:** Astro 7 / Cloudflare Worker / Vitest (server); Swift 6.4, SwiftUI, iOS 27, Xcode 27.2, XcodeGen,
Swift Testing (app); PostHog iOS SDK (last task only).

**Spec:** `docs/superpowers/specs/2026-11-03-ios-app-design.md`

## Global Constraints

- The website must not change: no page may look or behave differently, no endpoint may change its behaviour.
- Not a WebView wrapper: every screen is native SwiftUI.
- No password readable on the phone or in logs; never commit credentials, signing data, the team id or the site URL
  (the repo is public). App-specific values live in the git-ignored `ios/Config/Local.xcconfig`.
- iOS 27 minimum; built with Xcode 27.2 (`DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, since
  `xcode-select` still points at the Command Line Tools).
- No third-party Swift packages except the PostHog SDK in Task 12.
- Design: plain, Apple-like, calm; gold accent (`#9c7a2b` light / `#d4b05c` dark); grass-green pitch; no stat
  cards, no colour tints, no gradients; skeletons while loading; photos fade in; German copy, same wording as the
  site. Colours mirror the tokens in `src/styles/global.css` (`--bg`, `--surface`, `--fg`, `--muted`,
  `--hairline`, `--gold`, `--red-fg`, `--yellow-fg`, `--green-fg`, `--grey-fg`, light and dark).
- Tabs, in order, with labels: News, Aufstellungen, Mein Team, Scouting, Einstellungen.
- Excluded: /schnoeselmob page, coach pages and `/api/coach/…`, push notifications. Schnöselmob *posts* stay in
  the feed with comments, votes and polls.
- Server code follows the repo's conventions (comment density, naming, `json()`/`readJson()` from `src/lib/http.ts`);
  `npm test` and `npm run typecheck` (or the repo's typecheck script) green after every server task.

## Review Focus

1. A Kickbase token that has expired inside the app token: the endpoint's existing relogin sets a fresh `kb`
   cookie, and the app must receive and keep the rotated token (Task 1 test `rotates the token when a cookie is set`).
2. An undecryptable or foreign token (key rotated, garbage): treated as an empty session — signed out, never a
   500 (Task 1 test `treats a bad token as an empty session`).
3. A browser request (no `X-TonInsider-App` header) must pass through byte-for-byte unchanged, cookies and
   `Set-Cookie` included (Task 1 test `leaves browser requests alone`).
4. Coach posts built in before their minute (`publishedAt` in the future) and own posts' `pinnedUntil`: the app
   hides/unpins them by the clock exactly like `ArticleRow` (Task 5 test `hides posts until their minute`).
5. Offline launch: with a cached feed the app shows it with no error; with none, a calm empty state with retry;
   a failed refresh never clears what is shown (Task 5 test `keeps the cached feed when the refresh fails`).

### Task 1: App session adapter (server)

**Files:**
- Create: `src/lib/appSession.ts`, `src/lib/appSession.test.ts`
- Modify: `src/worker.ts` (wrap `handle`)

**Interfaces:**
- Produces:
  - Request header `X-TonInsider-App: 1` marks an app request; optional `Authorization: Bearer <token>`.
  - Response header `X-App-Token: <token>` whenever the session changed; `Set-Cookie` is stripped from app responses.
  - `token = seal(JSON.stringify(jar), CREDENTIALS_KEY)` with `seal`/`unseal` from `src/lib/vault.ts`;
    `jar: Record<string, string>` maps cookie name → raw cookie value as it appeared in `Set-Cookie`.
  - `export async function toCookieRequest(request: Request, key: string): Promise<{ request: Request; jar: Record<string, string> }>`
  - `export async function fromCookieResponse(response: Response, jar: Record<string, string>, key: string): Promise<Response>`
  - `export function isAppRequest(request: Request): boolean` — header present and path starts with `/api/` or
    `/data/` (nothing else is adapted).

- [ ] **Step 1: Write the failing tests** in `src/lib/appSession.test.ts` (use a test key made like the existing
  vault tests do):
  - `leaves browser requests alone`: `isAppRequest` is false without the header, and false for `/mein-team/` with it.
  - `turns the token into cookies and the site's own origin`: token sealing `{kb: "t1", kbc: "s1"}` → the new
    request has `cookie: kb=t1; kbc=s1`, `origin` equal to `new URL(url).origin`, no `authorization` header.
  - `starts empty without a token`: header only → `cookie` header absent, `jar` is `{}`.
  - `treats a bad token as an empty session`: `Bearer garbage` → `jar` `{}`, no throw.
  - `rotates the token when a cookie is set`: response with `Set-Cookie: kb=t2; Path=/; HttpOnly` → result has
    no `set-cookie`, has `x-app-token` that unseals to `{kb: "t2", kbc: "s1"}`.
  - `drops deleted cookies`: `Set-Cookie: kbc=; Expires=Thu, 01 Jan 1970 00:00:00 GMT` and `kb=deleted; Max-Age=0`
    → both gone from the new jar.
  - `no token header when nothing changed`: response without `Set-Cookie` → no `x-app-token`.
  - `keeps redirects`: a 303 with `Location: /mein-team/` keeps status and `location`.

- [ ] **Step 2: Run** `npx vitest run src/lib/appSession.test.ts` — Expected: FAIL (module not found).

- [ ] **Step 3: Implement** `src/lib/appSession.ts`. Parse `Set-Cookie` with `response.headers.getSetCookie()`;
  a cookie counts as deleted when `Max-Age=0` or its `Expires` is in the past. Rebuild the response with the same
  body/status and copied headers minus `set-cookie`.

- [ ] **Step 4: Wire it in `src/worker.ts`:** `fetch(request, env, ctx)`: if `isAppRequest(request)` — answer
  `503` JSON `{error: "Nicht verfügbar."}` when `env.CREDENTIALS_KEY` is missing; else
  `toCookieRequest` → `handle(adapted, env, ctx)` → `fromCookieResponse`. Otherwise `handle(request, env, ctx)`
  exactly as before. Never emit CORS headers (a cross-site page can't send the custom headers without a preflight,
  which is why the same-origin check may be satisfied for bearer requests).
